# vrcdog-server 功能适配审计

审计对象：独立 `vrcdog-server`、Tauri 内置本地服务、客户端连接流程和服务端控制台。

## 结论

独立服务端已经覆盖当前客户端使用的主要 API，并已补齐问卷功能以及远程“踢出”行为，可作为单机、自托管、小规模可信用户环境的部署基线。

它还不能定义为“所有功能均已完善的互联网生产服务”。主要限制是客户端身份自声明、管理员接口无会话/MFA/限速、任意 CORS、单机 JSON 状态、远程日志不可在控制台完整查看，以及内置本地服务重启后管理状态不持久化。

## 仍需优先补强

### P0：客户端身份真实性

注册、问卷提交、历史查询和删除都以客户端提交的 `user_id` 为依据。攻击者知道另一个用户 ID 时可模拟该用户。正式公网授权应增加由可信身份源签发、服务端可验证的短期令牌；仅增加一个由同一匿名注册接口返回的 token 不能解决身份冒用根因。

### P0：管理员接口防护

管理员密码通过 `x-vrcdog-admin-password` 随每个请求发送。虽然服务端保存 BCrypt 哈希，但没有会话过期、MFA、暴力破解限制和细粒度管理员角色。部署时必须使用 HTTPS、来源 IP 白名单和反向代理限速。

### P1：存储与并发

单个 JSON 文件适合单实例轻量部署，不适合大量问卷答案、统计分析或多个副本。下一阶段建议迁移到 SQLite/PostgreSQL，增加事务、索引、分页、保留策略和数据库迁移。

### P1：CORS 与媒体安全

服务端当前允许任意 Origin、Header 和 Method；Tauri 配置的 CSP 也为 `null`。问卷媒体 URL 由管理员配置并在客户端渲染。应增加允许来源列表、媒体域名白名单、严格 CSP，以及对 URL 的大小/类型/重定向约束。

### P1：可观测性

远程控制台的“终端日志”只显示控制台自身操作，不是远程容器完整日志。生产环境应使用 1Panel 容器日志或集中日志，并增加结构化审计记录、指标和告警。

### P2：产品能力

当前媒体为 URL 引用，不包含本地上传、转码和对象存储生命周期；问卷已支持管理员查看单份答卷详情及按当前问卷导出 Excel，但仍没有条件分支、匿名模式、定时发布/截止时间和汇总统计报表。这些不影响本次描述的基本问卷门禁，但属于标准问卷平台的后续增强项。

新增问卷界面当前使用简体中文文案，尚未接入项目已有的全部语言包。需要面向其他语言用户发布时，应先完成 i18n 键和各语言回退文案。
